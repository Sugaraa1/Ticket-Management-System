# Автомат тест (data-driven)

QA-ийн гараар хийдэг давтагдах шалгалтыг (жишээ нь: бүртгүүлэх хуудсанд 100 өөр өгөгдөл оруулж үзэх) автоматжуулна.

## Ойлголтууд

| Нэр | Юу вэ |
|---|---|
| **Апп** | Шалгах систем, төсөлд харьяалагдана. QA/Admin бүртгэнэ |
| **Орчин** | Апп-ын хаяг: `dev`, `staging` ... (`https://staging.shop.mn`) |
| **Өгөгдлийн файл** | Excel/CSV, мөр бүр нэг тест. **Олон сценарид дахин ашиглагдана** |
| **Сценари** | Нэг хуудас (жишээ: `/register`), түүний талбар ↔ файлын баганын холбоос, амжилтын нөхцөл |
| **Ажиллуулалт** | Сценари + файл + орчин → мөр бүрийн үр дүн |

## Урсгал

1. QA/Admin: **Апп бүртгэх** → орчны хаяг нэмэх
2. QA: **Өгөгдлийн файл оруулах** (жишээ загварыг татаж болно) — эсвэл 3-р алхамд автоматаар үүсгэнэ
3. QA: **Шинэ сценари** → хуудасны замаа оруулаад **"Хуудсыг шалгах"**. Систем хуудсыг нээж талбаруудыг харагдаж буй нэрээр нь (label, placeholder) олж, файлын баганатай автоматаар холбоно (`email` ↔ "Имэйл хаяг"). CSS selector мэдэх шаардлагагүй. Файл байхгүй бол **"Тест өгөгдөл үүсгэх"** дарна
4. **Ажиллуулах** → явц шууд харагдана → ✅/❌ хүснэгт, унасан мөрийн дэлгэцийн зураг, Excel татах
5. Унасан мөрүүдийг сонгоод **"Bug ticket үүсгэх"** → оролт, хүлээгдэж байсан ба бодит үр дүнтэй ticket үүсэж, зургууд хавсралт болно

## Файлын формат

| Тайлбар | email | password | хүлээгдэх |
|---|---|---|---|
| Зөв бүртгэл | `test{{random}}@mail.mn` | Pass123! | амжилттай |
| Буруу имэйл | bat@@mail | Pass123! | алдаа |
| Богино нууц үг | a@mail.mn | 12 | алдаа: 8-аас доошгүй |

- **хүлээгдэх**: `амжилттай` / `алдаа`, эсвэл `алдаа: текст`. Текст бичвэл хуудсанд тэр текст гарсан эсэхийг бас шалгана. Аль баганыг ашиглахыг сценари бүр өөрөө сонгоно (нэг файлд `хүлээгдэх_register`, `хүлээгдэх_login` байж болно)
- `{{random}}`: мөр бүрт шинэ 6 тэмдэгт, `{{row}}`: мөрийн дугаар, `{{timestamp}}`: одоогийн цаг
- Нууц үгийн талбарт холбосон багана үр дүнд `***` гэж харагдана

## Тест өгөгдөл автоматаар үүсгэх

"Хуудсыг шалгах"-ын дараа **"Тест өгөгдөл үүсгэх"** нь олдсон талбаруудаас Excel файл үүсгэж, талбаруудтай холбоно:

- **"Бүх талбар зөв"** мөр → `амжилттай`
- Талбар бүрийг ээлжлэн эвдсэн мөрүүд (бусад талбар зөв): хоосон (required), буруу имэйл, богино (minlength), min/max-аас гадуур, pattern-д таарахгүй, сонгоогүй, чагтлаагүй → `алдаа`
- Хариуг таах боломжгүй мөрүүд: хэт урт, SQL injection, XSS, кирилл/emoji, утас үсэгтэй → "хүлээгдэх" хоосон тул "Гараар шалгах" гарна, QA үр дүнг хараад шийднэ (500 алдаа, script ажилласан эсэх г.м.)

"Бүх талбар зөв" мөрийн утгууд (жишээ нь нэвтрэх хуудсанд жинхэнэ хэрэглэгч) сайтад тохирохгүй бол файлаа татаж засаад "Файл солих"-оор дахин оруулна.

## Үр дүнг хэрхэн тодорхойлдог вэ

"Автоматаар" горимд:
- алдааны мессеж (`.error`, `.invalid-feedback`, `[role=alert]` ...) эсвэл browser-ийн өөрийн шалгалт (required, type=email) гарвал **алдаа**
- хуудас шилжсэн, эсвэл амжилтын мессеж гарвал **амжилттай**

Эсвэл "URL нь ... агуулсан" / "Хуудсанд ... текст гарсан" нөхцөлийг сонгож болно.

## Техникийн бүтэц

- Browser ажлыг (хуудас шалгах, ажиллуулах) **`run_autotest_worker`** процесс DB-ийн дарааллаас авч гүйцэтгэнэ. Вэб серверт Chromium шаардлагагүй
- Мөр бүр шинэ (cookie-гүй) browser context дээр ажиллана. Мөр хооронд `AUTOTEST_ROW_DELAY_MS` (300ms) хүлээнэ
- Аюулгүй байдал: тест зөвхөн бүртгэлтэй орчны хаяг руу хандана. `169.254.x.x` (cloud metadata) үргэлж хаалттай. localhost, дотоод сүлжээг `AUTOTEST_ALLOW_PRIVATE_HOSTS=True` үед л зөвшөөрнө
- Эрх: автомат тестийг зөвхөн **QA, Admin** ашиглана (апп, орчин, файл, сценари, ажиллуулалт, үр дүн). Dev үр дүнг bug ticket-ээр (дэлгэцийн зураг хавсралттай) авна

## Одоогоор хийгдээгүй (дараагийн шатууд)

- Олон алхамт урсгал (нэвтрээд → сагсанд нэмэх → захиалах)
- Бичлэг хийж сценари үүсгэх
- API (mobile app-ын backend) сценари
- Тогтмол давтамжтай автоматаар ажиллуулах
