# Автомат тест (data-driven)

QA-ийн гараар хийдэг давтагдах шалгалтыг (жишээ нь: бүртгүүлэх хуудсанд 100 өөр өгөгдөл оруулж үзэх) автоматжуулна.

## Ойлголтууд

| Нэр | Юу вэ |
|---|---|
| **Апп** | Шалгах систем, **ангилал** (+ дэд ангилал)-д харьяалагдана — bug ticket тэр ангиллын баг руу чиглэнэ. QA/Admin бүртгэнэ |
| **Орчин** | Апп-ын хаяг: `dev`, `staging` ... (`https://staging.shop.mn`). Жинхэнэ сайтыг **Production** гэж тэмдэглэнэ (орчны жагсаалтын `Production` switch-ээр асааж/унтраана) |
| **Хуудас** | Апп-ын шалгах хуудас: нэр + зам (`Бүртгүүлэх` — `/register`). Сценари хуудсаа dropdown-оос сонгоно |
| **Тестийн хэрэглэгч** | Нэвтрэлт шаарддаг хуудсыг шалгахад: `QA` — `qa_test` / нууц үг (шифрлэгдэж хадгалагдана, дэлгэцэнд харагдахгүй). Мөн тэр хэсгийн **Нэвтрэлт → Веб** tab-д **нэвтрэх хуудсаа** сонгоно |
| **Өгөгдлийн файл** | Excel/CSV, мөр бүр нэг тест, ангилалд харьяалагдана. **Олон сценарид дахин ашиглагдана** |
| **Сценари** | Нэг хуудас (жишээ: `/register`), түүний талбар ↔ файлын баганын холбоос, амжилтын нөхцөл. Эсвэл **API сценари** — нэг HTTP хүсэлт (доор) |
| **Ажиллуулалт** | Сценари + файл + орчин → мөр бүрийн үр дүн |

## Урсгал

1. QA/Admin: **Апп бүртгэх** (ангилал сонгоно) → орчны хаяг, шалгах хуудсууд нэмэх
2. QA: **Өгөгдлийн файл оруулах** (жишээ загварыг татаж болно) — эсвэл 3-р алхамд автоматаар үүсгэнэ
3. QA: **Шинэ сценари** → орчин, хуудас, **"Хэн болж шалгах"** (нэвтрэхгүй / тестийн хэрэглэгч)-аа сонгоод **"Хуудсыг шалгах"**. Систем хуудсыг нээж талбаруудыг харагдаж буй нэрээр нь (label, placeholder) олж, файлын баганатай автоматаар холбоно (`email` ↔ "Имэйл хаяг"). CSS selector мэдэх шаардлагагүй. Файл байхгүй бол **"Тест өгөгдөл үүсгэх"** дарна
4. **Ажиллуулах** → явц шууд харагдана → ✅/❌ хүснэгт, унасан мөрийн дэлгэцийн зураг, Excel/CSV татах
5. Унасан мөрүүдийг сонгоод **"Bug ticket үүсгэх"** → оролт, хүлээгдэж байсан ба бодит үр дүнтэй ticket үүсэж, зургууд хавсралт болно. Ангилал/дэд ангилал апп-аас бөглөгдөж зөв баг руу чиглэнэ, төслөө сонгоно

## Workflow

Autotest-ийн хуудас бүрийн гарчгийн хажууд **Workflow** товч байна. Түүнийг дарахад тухайн хуудсан дээр юу хийхийг дугаартай алхам, нэг мөр тайлбар, бодит жишээгээр баруун талаас харуулна (код мэдэхгүй хүнд зориулсан):

| Хуудас | Workflow |
|---|---|
| Нүүр, апп бүртгэх, апп | Апп → Орчин → Хуудас → Тестийн хэрэглэгч → Өгөгдлийн файл → Сценари → Ажиллуулах → Үр дүн → Bug ticket (жишээ нь тухайн апп-ын орчин, хуудас, хэрэглэгчээс) |
| Шинэ сценари (веб) | Хуудас сонгох → Хуудсыг шалгах → Талбар ↔ багана → Тест өгөгдөл үүсгэх → Хүлээгдэх үр дүн → Хадгалах. Хуудас сонгоход, "Хуудсыг шалгах"-ын дараа олдсон талбарууд, үүсэх мөрүүдээр (✓ Бүх талбар зөв, ✗ … хоосон) шинэчлэгдэнэ |
| Шинэ API сценари | Method + зам → Body → Хэн болж шалгах → Хүлээгдэх үр дүн → Хадгалах |
| Сценари | (Нэвтрэх) → Файл + орчин сонгох → Ажиллуулах → Тестийн алхмууд → Үр дүн → Bug ticket → Эрх шалгах. Сценари бүрийн бодит утгаар автоматаар үүснэ |
| Ажиллуулалт | Явц → Мөр бүрийн үр дүн → Дэлгэцийн зураг → Унасан мөр сонгох → Bug ticket → Дахин ажиллуулах |
| Өгөгдлийн файл | Загвар татах → Бөглөх → Оруулах → Browser-т засах → Сценарид ашиглах |

Олон хуудсыг хамардаг workflow-д тухайн хуудсанд хийх алхам «Энэ хуудсанд» шошготой тодорно; «заавал биш» алхам тасархай хүрээтэй. Алхмуудыг `apps/autotest/guide.py`-д тодорхойлно.

## Сценарийн хуудас

Гурван таб:

- **Ажиллуулах**: файл, орчноо сонгоод ажиллуулах; эрх шалгах (QA/Admin)
- **Тестийн алхмууд**: тест мөр бүрт хийх алхмуудыг дарааллаар нь харуулна. Код мэдэхгүй хүн ч ойлгоно. Сценарийн тохиргооноос автоматаар үүсдэг тул тусад нь зурах шаардлагагүй, сценари засахад өөрөө шинэчлэгдэнэ
- **Түүх**: өмнөх ажиллуулалтууд

Тестийн алхмуудын жишээ (нэвтрэх хуудас):

```
① Хуудас нээх          /accounts/login/
② «Нэвтрэх нэр» бөглөх  qa_test        ← username багана
③ «Нууц үг» бөглөх      ***            ← password багана
④ «Нэвтрэх» товч дарах
⑤ Үр дүнг шалгах        Алдаа гарна · "Нууц үг буруу"
```

- Файл, мөрөө сонгоход утгууд тэр мөрийнх болно. Файл байхгүй бол аль баганаас авахыг харуулна
- Тестийн хэрэглэгчээр шалгадаг сценарид эхэнд **Нэвтрэх** алхам нэмэгдэнэ. API сценари: Нэвтрэх (token) → Хүсэлт илгээх (body-той) → Үр дүнг шалгах
- Нууц үг, token `***` болж харагдана. Сүүлийн алхам хүлээгдэх үр дүнгээр ногоон (амжилттай) / улаан (алдаа) / саарал (гараар шалгах) өнгөтэй

## API сценари

Mobile app-ын backend г.м. API-г browser-гүйгээр шалгана. Апп дотроос **"Шинэ сценари ▾" → "API"**.

- **Method** (GET/POST/PUT/PATCH/DELETE), **Хаяг** (`/api/users/{{id}}`), **Header** (`Нэр: утга` мөр бүрт), **Body (JSON)**
- `{{багана}}` нь файлын нүдний утгаар орлогдоно (`{{random}}` г.м. placeholder ч ажиллана). JSON body-д утга escape хийгдэнэ, хашилтыг өөрөө бичнэ: `{"email": "{{email}}", "age": {{age}}}`. Хаягт URL-encode хийгдэнэ
- Мөр бүр нэг хүсэлт. **хүлээгдэх** багана: `201`, `400: мессеж` (status код + хариунд гарах текст), эсвэл `амжилттай` (< 400) / `алдаа` (≥ 400)
- **Хэн болж шалгах**: тестийн хэрэглэгч сонговол эхлээд апп-ын **API нэвтрэх зам** руу POST хийнэ (**Тестийн хэрэглэгчид → API** tab-д зам, body загвар `{"username": "{{username}}", "password": "{{password}}"}`, token-ий угтварыг тохируулна; веб сценарийн нэвтрэх хуудас нь **Веб** tab-д). Хариунаас token (`access_token`, `token`, `access`, `jwt` ...) олдвол `Authorization: Bearer ...` гэж явуулна, үгүй бол cookie session ашиглана
- Үр дүнд мөр бүрийн хүсэлтийг `curl` командаар, хариуг JSON-оор харуулна. Нууц үг, token агуулсан багана/header `***` болно
- Redirect бүрийг аюулгүй байдлын шалгалтаар (доор) шалгана. Хүсэлтийн хооронд өгөгдөл дамжуулах (нэг хариунаас ID авч дараагийн хүсэлтэд ашиглах) одоогоор байхгүй

## Өгөгдлийн файл засах

Файлын нэр дээр дарахад browser дотроо хүснэгтээр нээгдэнэ: мөр нэмэх/засах/устгах, хайх, **багана нэмэх / нэр солих / устгах**.

- Сценарид ашиглагдаж буй багана түгжээтэй (засах горимд 🔒 тэмдэгтэй) — нэр солих, устгах боломжгүй (сценари эвдэрнэ)
- Тестийн хэрэглэгчийн роль (`QA`, `Dev` ...) badge-аар харагдана
- Excel файлыг хадгалахад өнгө, баганын өргөн г.м. формат хэвээр үлдэнэ

## Production орчин

Тест хэрэглэгчийн оронд жинхэнэ форм илгээж, жинхэнэ хүсэлт явуулдаг — үүссэн өгөгдөл тухайн сайтын DB-д үлдэнэ. Иймд өгөгдөл бичдэг тестийг `local`/`staging` дээр ажиллуулна.

Production гэж тэмдэглэсэн орчныг сонгоод **Ажиллуулах**, **Эрх шалгах**, **Дахин ажиллуулах** дарахад "жинхэнэ өгөгдөл үүсгэж, мэдэгдэл илгээж болно" гэсэн баталгаажуулалт гарна. Зөвшөөрвөл ажиллана.

## Эрх шалгах

Сценарийн хуудсан дээрх **"Эрх шалгах"** хүснэгтэд хэрэглэгч бүрт (Нэвтрэхгүй, QA, Dev ...) хуудас **Нээлттэй / Хаалттай** байх ёстойг сонгоод орчноо сонгож **"Шалгах"** дарна. Өгөгдлийн файл хэрэггүй.

- Хэрэглэгч бүрээр нэвтэрч хуудсыг нээнэ. Сценарийн талбар харагдвал **нээлттэй**, үгүй бол (HTTP 403/404, нэвтрэх хуудас руу шилжүүлсэн, "эрхгүй" хуудас) **хаалттай**
- Хүлээлттэй таарвал ✅, таараагүй бол ❌ + дэлгэцийн зураг → bug ticket үүсгэж болно
- Сонголт сценари дээр хадгалагдана — "Дахин ажиллуулах" ижил хүснэгтээр шалгана

## Файлын формат

`.xlsx` эсвэл `.csv` оруулна. Бүх татах товч (загвар, өгөгдлийн файл, үр дүн) Excel / CSV сонголттой — хадгалсан форматаас үл хамааран хөрвүүлж татна.

| Тайлбар | email | password | хүлээгдэх |
|---|---|---|---|
| Зөв бүртгэл | `test{{random}}@mail.mn` | Pass123! | амжилттай |
| Буруу имэйл | bat@@mail | Pass123! | алдаа |
| Богино нууц үг | a@mail.mn | 12 | алдаа: 8-аас доошгүй |

- **хүлээгдэх**: `амжилттай` / `алдаа`, эсвэл `алдаа: текст`. Текст бичвэл хуудсанд тэр текст гарсан эсэхийг бас шалгана. Аль баганыг ашиглахыг сценари бүр өөрөө сонгоно (нэг файлд `хүлээгдэх_register`, `хүлээгдэх_login` байж болно)
- `{{random}}`: мөр бүрт шинэ 6 тэмдэгт, `{{row}}`: мөрийн дугаар, `{{timestamp}}`: одоогийн цаг
- Нууц үгийн талбарт холбосон багана үр дүнд `***` гэж харагдана

## Тест өгөгдөл автоматаар үүсгэх

"Хуудсыг шалгах"-ын дараа **"Тест өгөгдөл үүсгэх"** нь олдсон талбаруудаас Excel файл үүсгэж, талбаруудтай холбоно:

- **"Бүх талбар зөв"** мөр → `амжилттай`
- Талбар бүрийг ээлжлэн эвдсэн мөрүүд (бусад талбар зөв): хоосон (required), буруу имэйл, богино (minlength), min/max-аас гадуур, pattern-д таарахгүй, сонгоогүй, чагтлаагүй → `алдаа`
- Хариуг таах боломжгүй мөрүүд: хэт урт, SQL injection, XSS, кирилл/emoji, утас үсэгтэй → "хүлээгдэх" хоосон тул "Гараар шалгах" гарна, QA үр дүнг хараад шийднэ (500 алдаа, script ажилласан эсэх г.м.)

"Бүх талбар зөв" мөрийн утгууд (жишээ нь нэвтрэх хуудсанд жинхэнэ хэрэглэгч) сайтад тохирохгүй бол файлаа татаж засаад "Файл солих"-оор дахин оруулна.

## Үр дүнг хэрхэн тодорхойлдог вэ

"Автоматаар" горимд:
- алдааны мессеж (`.error`, `.invalid-feedback`, `[role=alert]` ...) эсвэл browser-ийн өөрийн шалгалт (required, type=email) гарвал **алдаа**
- хуудас шилжсэн, эсвэл амжилтын мессеж гарвал **амжилттай**

Эсвэл "URL нь ... агуулсан" / "Хуудсанд ... текст гарсан" нөхцөлийг сонгож болно.

- Илгээсний дараа хуудсаас гарсан хүсэлтүүд (AJAX) дуусахыг хүлээнэ. Энэ хооронд гараад алга болдог toast/snackbar/alert мессежийг барьж үр дүнд тооцно
- Заавал бөглөх талбарын улаан `*` г.м. үсэг, тоогүй тэмдгийг алдаа гэж тооцохгүй
- Өөр талбараас хамаарч идэвхждэг талбар (ангилал → дэд ангилал) 5 секунд хүртэл хүлээнэ
- Excel-ийн огноо нүд `2024-01-05` болж уншигдана, `type=date` талбарт тохирох форматаар бөглөгдөнө
- Талбарын selector-т React/MUI-ийн ачаалах бүрт өөрчлөгддөг id (`:r1:`, `mui-123`)-г ашиглахгүй — `name`, label-аар олно

## Техникийн бүтэц

- Browser ажлыг (хуудас шалгах, ажиллуулах) **`run_autotest_worker`** процесс DB-ийн дарааллаас авч гүйцэтгэнэ. Вэб серверт Chromium шаардлагагүй
- Мөр бүр шинэ browser context дээр ажиллана. Мөр хооронд `AUTOTEST_ROW_DELAY_MS` (300ms) хүлээнэ
- Нэвтрэлт: сценарид тестийн хэрэглэгч сонгосон бол worker эхлээд нэвтрэх хуудсыг нэг удаа бөглөж (нууц үгийн талбар + түүний формын нэвтрэх нэрийн талбарыг — `autocomplete=username`, нэр/id-д `user`/`login`/`email` агуулсан, үгүй бол эхний текст талбар — автоматаар олно), session-ийг хадгалаад мөр бүрийг тэр session-тэй ажиллуулна. Нэвтэрч чадахгүй бол сайтын алдааны мессежтэй зогсоно. Ажиллах явцад session дуусаж нэвтрэх хуудас руу шилжүүлбэл дахин нэвтэрч тухайн мөрийг давтана. Нууц үг `SECRET_KEY`-ээс гаргасан түлхүүрээр (Fernet) шифрлэгдэнэ — `SECRET_KEY` солигдвол нууц үгийг дахин оруулна
- Нэвтэрсэн тест бодит өгөгдөл үүсгэнэ (мөр бүр нэг ticket г.м.) — зөвхөн `local`/`staging` орчинд, тусгай тестийн хэрэглэгчээр ажиллуулна. CAPTCHA, 2FA, SSO-той нэвтрэлт одоогоор дэмжигдэхгүй
- Аюулгүй байдал: тест зөвхөн бүртгэлтэй орчны хаяг руу хандана. `169.254.x.x` (cloud metadata) үргэлж хаалттай. localhost, дотоод сүлжээг `AUTOTEST_ALLOW_PRIVATE_HOSTS=True` үед л зөвшөөрнө
- Эрх: автомат тестийг зөвхөн **QA, Admin** ашиглана (апп, орчин, файл, сценари, ажиллуулалт, үр дүн). Dev үр дүнг bug ticket-ээр (дэлгэцийн зураг хавсралттай) авна

## Одоогоор хийгдээгүй (дараагийн шатууд)

- Олон алхамт урсгал (нэвтрээд → сагсанд нэмэх → захиалах)
- Бичлэг хийж сценари үүсгэх
- API хүсэлтийн хооронд өгөгдөл дамжуулах (chaining)
- Тогтмол давтамжтай автоматаар ажиллуулах
